# Runbook: AmneziaWG split-tunnel «всё через VPN, кроме России»

> **Это инструкция для Claude Code, запущенного напрямую на VPN-сервере.**
> Прочитай её целиком ПЕРВОЙ, прежде чем что-либо делать. Здесь — цель,
> ограничения, безопасность и точный порядок действий.

---

## 1. Цель

На сервере развёрнут **AmneziaWG (WireGuard)**. Пользователи вынуждены вручную
включать/выключать VPN, заходя на российские сайты, где он не нужен.

Нужно настроить **split tunneling по IP** так, чтобы:

- весь трафик шёл **через VPN**,
- **кроме российских подсетей (GeoIP = RU)** — они идут напрямую, мимо туннеля.

Тогда включать/выключать VPN вручную не нужно: Рунет работает напрямую,
зарубежные сайты — через VPN, автоматически.

## 2. Как это устроено технически

В WireGuard маршрутизацией на клиенте управляет строка **`AllowedIPs`** в
клиентском конфиге. Клиент заворачивает в туннель только перечисленные там IP.

Задача сводится к замене:

```
AllowedIPs = 0.0.0.0/0            # было: весь трафик в VPN
```
на
```
AllowedIPs = <весь мир> МИНУС <российские подсети>   # стало: всё, кроме RU
```

Список «весь мир без RU» вычисляется автоматически: берём `0.0.0.0/0`,
вычитаем RU-подсети (GeoIP), получаем ~тысячи CIDR-блоков. Их и подставляем
в `AllowedIPs`.

> **Важно (ограничение подхода):** маршрутизация идёт по IP, а не по доменам.
> Российский сайт на зарубежном CDN (Cloudflare) всё равно пойдёт через VPN;
> зарубежный сайт на российском хостинге — напрямую. Для 95% случаев это
> работает отлично. Точная маршрутизация «по домену» требует sing-box/xray —
> это отдельная задача, в этом runbook не делаем.

## 3. Жёсткие правила безопасности

1. **НИКОГДА не выводи и не логируй приватные ключи** (`PrivateKey`,
   `PresharedKey`) из конфигов. При обработке файлов трогай только строку
   `AllowedIPs`.
2. **Всегда делай бэкап** каждого конфига перед изменением
   (`*.conf.bak-YYYYMMDD-HHMMSS`).
3. **Сначала покажи план и diff, дождись подтверждения пользователя**, только
   потом меняй боевые конфиги и перезапускай интерфейс.
4. Меняй **только `AllowedIPs`**. Не трогай ключи, `Endpoint`, `Address`,
   `DNS`, порты, Jc/Jmin/Jmax/S1/S2/H1..H4 (обфускация AmneziaWG) и прочее.
5. Имей готовый **rollback** (раздел 8) до любого изменения.

## 4. Фаза I — Разведка (ничего не менять!)

Определи окружение и доложи пользователю. Собери:

- **ОС**: `cat /etc/os-release`
- **Как развёрнут AmneziaWG**:
  - Docker: `docker ps --format '{{.Names}}\t{{.Image}}' | grep -i amnezia`
    (типичное имя контейнера `amnezia-awg`).
  - systemd/host: `systemctl list-units | grep -iE 'wg|amnezia'`,
    наличие `awg` / `wg` бинарей: `which awg wg wg-quick`.
- **Где конфиги** (проверь эти пути):
  - `/opt/amnezia/awg/` (частый путь Amnezia)
  - `/etc/amnezia/`
  - `/etc/wireguard/`
  - внутри контейнера: `docker exec <name> ls /opt/amnezia/awg/ /etc/wireguard/`
- **Серверный интерфейс** (`wg0.conf` / `awg0.conf`) и **клиентские конфиги**
  (файлы клиентов, либо `[Peer]`-секции на сервере).
- **Текущий `AllowedIPs`** в клиентских конфигах и **`DNS`**.
- **Утилита управления интерфейсом**: `awg-quick` или `wg-quick`, имя
  интерфейса (`awg0`/`wg0`).

Выведи пользователю короткий отчёт: ОС, способ развёртывания, пути к конфигам,
число клиентов, текущий `AllowedIPs` и `DNS`. **Останься в режиме «только
чтение», пока пользователь не подтвердит план.**

## 5. Фаза II — Установка инструментов

Скрипт-генератор лежит рядом: `scripts/generate_allowed_ips.sh`
(обёртка) и `scripts/allowed_ips.py` (логика). Нужен `python3`.

- Проверь: `python3 --version`.
- Скрипт не требует сторонних библиотек (чистый stdlib, модуль `ipaddress`).
- Источник RU-подсетей по умолчанию:
  `https://www.ipdeny.com/ipblocks/data/aggregated/ru-aggregated.zone`
  (запасной: `https://www.ipdeny.com/ipblocks/data/countries/ru.zone`).
  Если исходящий доступ ограничен — спроси у пользователя разрешённый
  источник или загрузи список заранее в файл и передай путь.

## 6. Фаза III — Генерация списка AllowedIPs

Запусти генератор — он скачает RU-список, вычтет его из `0.0.0.0/0` и выдаст
готовую строку `AllowedIPs`:

```bash
bash scripts/generate_allowed_ips.sh --out /tmp/allowed_ips.txt
```

Проверь результат:
- файл содержит одну строку `AllowedIPs = 1.0.0.0/8, 2.0.0.0/7, ...`;
- российские диапазоны в неё НЕ входят (спот-проверка: например, подсеть
  Яндекса `77.88.0.0/18` или Сбера не должна попадать в список — раздел 9);
- размер разумный (обычно несколько тысяч CIDR).

## 7. Фаза IV — Применение к конфигам

**Сначала покажи diff одного конфига пользователю и получи «да».** Затем:

1. Для каждого клиентского конфига: бэкап → замена строки `AllowedIPs = ...`
   на сгенерированную. Скрипт `scripts/apply_to_configs.sh` делает это
   безопасно (бэкап + замена только `AllowedIPs`, ключи не трогаются):

   ```bash
   # dry-run: показать, что изменится, ничего не записывая
   bash scripts/apply_to_configs.sh --dir <CONFIG_DIR> --allowed /tmp/allowed_ips.txt --dry-run

   # применить
   bash scripts/apply_to_configs.sh --dir <CONFIG_DIR> --allowed /tmp/allowed_ips.txt
   ```

2. Если клиенты раздаются через приложение AmneziaVPN — пользователю нужно
   **перевыпустить/переотправить конфиги** клиентам (новый `AllowedIPs`
   применяется на стороне клиента). Объясни это явно.

3. **Серверный `awg0.conf`/`wg0.conf` в `AllowedIPs` менять НЕ нужно** —
   split-tunnel это клиентская настройка. На сервере убедись только, что
   форвардинг и NAT уже настроены (они и так работают, раз VPN функционирует).

## 8. Фаза V — Обновление по расписанию (cron)

RU-подсети меняются. Поставь еженедельное обновление:

```bash
bash scripts/install_cron.sh --dir <CONFIG_DIR>
```

Это создаёт `/etc/cron.weekly/amneziawg-ru-split` (или crontab-запись),
который пересобирает список и обновляет конфиги, делая бэкап. Логи —
в `/var/log/amneziawg-ru-split.log`.

## 9. Фаза VI — Проверка

1. **RU идёт напрямую, зарубеж — через VPN.** С клиента:
   - `curl -s https://ipinfo.io/json` при заходе на зарубежный ресурс должен
     показывать IP/страну сервера VPN;
   - трассировка/almаршрут к российскому IP (например `ping ya.ru`) должен
     идти НЕ через туннель (проверь `ip route get <ru_ip>` — не через
     wg-интерфейс).
2. **Нет утечек DNS** — оставь `DNS` как был (через VPN) либо надёжный
   резолвер.
3. **Спот-проверка списка**: убедись, что известная RU-подсеть отсутствует в
   `allowed_ips.txt`, а известная зарубежная (например `1.1.1.0/24`
   Cloudflare) присутствует.

## 10. Rollback

Каждый конфиг имеет бэкап `*.conf.bak-*`. Откат:

```bash
bash scripts/rollback.sh --dir <CONFIG_DIR>          # вернуть последние бэкапы
```
или вручную: `cp client.conf.bak-<ts> client.conf`, затем перезапустить
интерфейс: `awg-quick down awg0 && awg-quick up awg0` (или перезапуск
Docker-контейнера Amnezia). Удалить cron: `rm /etc/cron.weekly/amneziawg-ru-split`.
